## Pi SDK 0.84.2 实际提供的轮子 (本轮调研发现)

  - thinking：`set_thinking_level` / `cycle_thinking_level` / `get_available_thinking_levels`
  - queue：`set_steering_mode` / `set_follow_up_mode`
  - compaction：`compact` / `set_auto_compaction`

## 关键发现

**我们 v0.4.2 step 1 干的事，Pi SDK 0.84.2 都已经提供了**。我们的 sidecar 完全是**手写实现了一份 1:1 的 `runRpcMode`**。结论：sidecar 应该 100 行 wrapper，剩下交给 Pi SDK。

## v0.5.0 方案

### A. **Sidecar 重写 (sidecar/src/index.mjs 100 行)**

```js
// v0.5.0 sidecar: 100 行 wrapper，调 Pi SDK runRpcMode
// 不再手写 stdin/stdout 协议、不再手写 40+ case event 映射、不再手写 retry/watchdog
// 这些都走 runRpcMode + AgentSessionRuntime

import { runRpcMode } from '@earendil-works/pi-coding-agent/modes/rpc/rpc-mode';
import { createAgentSessionRuntime } from '@earendil-works/pi-coding-agent/core/agent-session-runtime';
import { SessionManager } from '@earendil-works/pi-coding-agent/core/session-manager';
import { createModels, createProvider } from '@earendil-works/pi-ai';
import { openaiCompletionsStream, openaiCompletionsStreamSimple } from '@earendil-works/pi-ai/api/openai-completions';
import { resolveCliModel } from '@earendil-works/pi-coding-agent/cli/model-resolver.js';

// 1. 读 stdin 第一行: FE config (workspacePath, provider, model, apiKey, baseUrl, sessionId, ...)
// 2. 创 user-custom provider (if baseUrl)
// 3. 创 SessionManager per-workspace 隔离
// 4. createAgentSessionRuntime factory
// 5. setRuntimeApiKey
// 6. runRpcMode(runtime) — Pi SDK 接管剩下所有事

const readline = createInterface({ input: process.stdin });
const firstLine = await new Promise((resolve) => readline.once('line', resolve));
const config = JSON.parse(firstLine);

const userCustomProvider = config.baseUrl ? createProvider({ ... buildUserCustomProvider(config) ... }) : null;

const sessionManager = SessionManager.create(
  config.workspacePath,
  `${getAgentDir()}/sessions/${sha256(config.workspacePath).slice(0, 16)}`,
  { id: config.sessionId ?? `sess-${Date.now()}-${Math.random().toString(36).slice(2, 8)}` },
);
if (existingFile) sessionManager.setSessionFile(existingFile);

const runtime = await createAgentSessionRuntime(async ({ cwd, agentDir, sessionManager: sm }) => {
  const model = await resolveCliModel({ provider: config.provider, model: config.model, baseUrl: config.baseUrl }, modelRuntime);
  if (config.apiKey) await modelRuntime.setRuntimeApiKey(model.provider, config.apiKey);
  if (userCustomProvider) modelRuntime.registerNativeProvider(userCustomProvider);
  return createAgentSessionFromServices({ services, sessionManager: sm, model, ... });
}, { cwd: config.workspacePath, agentDir: getAgentDir(), sessionManager });

await runRpcMode(runtime);  // 接管 stdin/stdout
```

**直接用 Pi SDK 0.84.2 已经实现的协议、retry、watchdog、backpressure、extension UI、compaction**，不重写。

### B. **FE 端重写 (chat store + Tauri command)**

**之前**: FE 自己定义 ServerToClient 协议，chat store 监听 stream events 累积 state
**之后**: FE 走 Pi SDK RpcCommand 协议，FE 端用 pull 模型 (get_state/get_messages) 拿全状态 + push events 增量更新

FE 端 tauri.ts 命令：
- `sendPrompt(content, config)` → 调 runRpcMode 后的 `prompt` command
- `abort()` → 调 `abort` command
- `setModel(provider, modelId)` → 调 `set_model` command
- `setThinkingLevel(level)` → 调 `set_thinking_level` command
- `compactSession()` → 调 `compact` command
- `fork(entryId)` / `clone()` / `switchSession(path)` → 调对应 command

FE 端事件处理：
- 不用手写 30+ case
- 订阅 `chat:event` 接收完整 AgentSessionEvent 协议
- 用 `get_state` 初始化，用 events 增量更新

**这才是真正的"用 Pi SDK 的轮子"**。FE 端不用关心 event 协议细节（协议走 Pi SDK 的 RpcEvent），不用手写 retry/watchdog/permission 任何逻辑。

### C. **Tauri command 端重写 (sidecar.rs + lib.rs)**

**之前**: 手写 stdin 协议 (`config`/`prompt`/`abort`/`permission_response`/`set_permission_mode`/`compact_session` 6 个 stdin 命令)
**之后**: 走 Pi SDK RPC 协议 (40+ RpcCommand)

Tauri command 简化：
- 启 sidecar (直接 `node @earendil-works/pi-coding-agent/rpc-entry` 或者我们的 100 行 wrapper)
- 写第一行 config (workspacePath, provider, model, apiKey, baseUrl, sessionId)
- 后续通过 stdio 透传 RpcCommand 跟 RpcEvent (Tauri 不用解析)
- 持久化 `per_workspace_session_id` 用 Pi SDK 的 `get_session_stats` 拿 `sessionId`

这样 Tauri 端不用理解任何 LLM 协议，纯粹是个 stdin/stdout 桥。

## 风险

1. **Pi SDK 0.84.2 API stability**: 0.84.2 是 2026 年的 release, API 还在变动. 但 `runRpcMode` 是 stable entry point (有 `rpc-entry.js`)
2. **FE 体验影响**: 重写 chat store 期间 chat UI 可能短暂不能用 (有 `git restore` 回滚机制)
3. **session 迁移**: v0.4.2 step 1 的 per-workspace sessionId 跟 v0.5.0 不兼容 (Pi SDK 0.84.2 内部 session 格式可能不同)，但 session 在 Pi SDK `~/.pi/agent/sessions/` 是 jsonl 格式，理论可读
4. **测试覆盖**: smoke test (8/8 PASS) 用的是手写协议，需要重写为 Pi SDK RPC 协议 client

## 决策

需要 user 确认：
1. v0.5.0 大重构 vs 继续打补丁 (推荐大重构)
2. Phase 1 先做 sidecar 重写 (低风险，纯 sidecar 内部，不影响 FE)
3. Phase 2 Tauri 端 (medium 风险)
4. Phase 3 FE 端 (高风险，UI 短暂不 work)
5. Phase 4 文档 + 测试

**推荐**: 同意大重构，按 Phase 1 → 2 → 3 → 4 顺序执行，每个 Phase 单独验证。
