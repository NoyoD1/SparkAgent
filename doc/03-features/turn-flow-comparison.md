# Chat Turn 流式渲染 · 4 个方案对比

> **生成时间**: 2026-08-18 21:21
> **目的**: user 拍板 #3 turn 流式效果具体选哪种 — 4 个候选方案的可视化对比
> **场景假设**: 用户发"帮我读 README.md 总结一下,然后写一个 hello.js,最后跑 node 跑它"
> **LLM 实际做的事**: think → read README → think → write hello.js → think → bash node hello.js → final text
>
> 4 个方案的区别在于**怎么把这条 thinking + tool + final 事件流渲染给用户**。

---

## 方案 A · 平铺流(Pi TUI / Pi SDK 原生风格)

> **核心**: 完全按事件流顺序平铺,**不分组**,无"步骤 N"标题。每个 thinking/tool 是一个独立 inline 块,默认折叠。
> **改 StepGroup**: 删,改 ChatMessage 平铺。

```
👤 帮我读 README.md 总结一下,然后写一个 hello.js,最后跑 node 跑它

─────────────────────────────────────────────────────────────────

🤖  ┌ 思考                                  [▼]                       ← 折叠按钮
   ├──────────────────────────────────────────────────────────────
   │ 用户要 3 件事: 1) 读 README 2) 写 hello.js 3) 跑 node
   └──────────────────────────────────────────────────────────────

   ┌ read          README.md                              完成 ✓     ← 工具块
   ├──────────────────────────────────────────────────────────────
   │ # Pi Agent  ← README 前几行预览
   │ 本地优先 + BYOK + 桌面优先的 AI Agent 客户端...
   │                                                  100 行 (点开)  ← 折叠看完整
   └──────────────────────────────────────────────────────────────

   ┌ 思考                                  [▼]
   ├──────────────────────────────────────────────────────────────
   │ README 说 ... 接下来写 hello.js
   └──────────────────────────────────────────────────────────────

   ┌ write         hello.js                                完成 ✓
   ├──────────────────────────────────────────────────────────────
   │ const msg = "Hello, Pi Agent!";
   │ console.log(msg);
   │                                                  写入 4 行
   └──────────────────────────────────────────────────────────────

   ┌ 思考                                  [▼]
   ├──────────────────────────────────────────────────────────────
   │ 现在跑一下
   └──────────────────────────────────────────────────────────────

   ┌ bash          node hello.js                           完成 ✓
   ├──────────────────────────────────────────────────────────────
   │ → Hello, Pi Agent!                                        [点开]
   └──────────────────────────────────────────────────────────────

   ── 最终回复 ──
   完成. README 主要说 Pi Agent 是本地优先的 BYOK AI 客户端 ...
   hello.js 已写入,node 跑通输出 "Hello, Pi Agent!"。
```

**特点**:
- ✅ 视觉最"事件流",无虚构分组
- ✅ 多次 think + tool 嵌套时仍清晰(每块独立折叠)
- ✅ thinking 折叠后不占空间
- ❌ thinking + tool 块多时,行数偏长
- ❌ 没有"这次 LLM 分几步"的概览(没有 N/M 进度)

**改 StepGroup**: 🟢 小(删 300 行,改 ChatMessage ~50 行平铺)

---

## 方案 B · Cursor 卡片风格

> **核心**: thinking 灰底 inline 持续显示(不折叠),tool call 是独立一行卡片(可点开看 result),无"步骤 N"标题。
> **改 StepGroup**: 改视觉(thinking 不折叠 + tool 卡片化),删标题。

```
👤 帮我读 README.md 总结一下...

─────────────────────────────────────────────────────────────────

🤖  💭 思考中...                                                       ← 持续显示
   用户要 3 件事: 1) 读 README 2) 写 hello.js 3) 跑 node
   (可滚动, thinking 累积在这里)

   ├─ [read README.md]   ✓   100 行                          1.2s     ← 卡片
   ├─ [write hello.js]   ✓   4 行                            0.3s
   └─ [bash node hello.js] ✓  → Hello, Pi Agent!              0.5s

   ── 最终回复 ──
   完成. README 主要说 Pi Agent 是本地优先的 BYOK AI 客户端 ...
```

**特点**:
- ✅ tool 视觉权重对(每行卡片)
- ✅ thinking 一直可见(用户能看到 LLM 在想什么)
- ❌ thinking 长时滚得很长,占视觉焦点
- ❌ 没有"步骤 N"分组概览

**改 StepGroup**: 🟡 中(改视觉 + 删标题 ~80 行)

## 方案 C · Claude Code web 风格

> **核心**: assistant message 一次性完整显示,tool 调用作为 message 内的嵌套卡片(不分组,不标步骤),thinking **不显示**。
> **改 StepGroup**: 删,改 ChatMessage 把 tool 当 nested card 渲染,thinking 完全藏起来。

```
👤 帮我读 README.md 总结一下...

─────────────────────────────────────────────────────────────────

🤖  完成. README 主要说 Pi Agent 是本地优先的 BYOK AI 客户端 ...
   hello.js 已写入,node 跑通输出 "Hello, Pi Agent!"。
   
   ▾ 调用了 3 个工具                                              ← 折叠点
   ├─ read README.md
   ├─ write hello.js
   └─ bash node hello.js
```

**特点**:
- ✅ 跟主流 Claude Code web 一致
- ✅ final answer 视觉权重最大
- ❌ thinking 完全看不到(用户不知道 LLM 怎么想的)
- ❌ tool 折叠了看不到细节
- ❌ 信息密度高时找不到 tool 在哪调过

**改 StepGroup**: 🟡 中(改 ChatMessage 主体 + 删 StepGroup,改 nested card ~150 行)

---

## 方案 D · 混合(默认折叠 step + 平铺内容)

> **核心**: 保留 step group 概念但简化:每 turn 1 行 `<details>` summary 默认折叠,点开看平铺内容(thinking + tool 按顺序平铺)。
> **改 StepGroup**: 保留外壳,改用 `<details>` 默认折叠,内部平铺。

```
👤 帮我读 README.md 总结一下...

─────────────────────────────────────────────────────────────────

🤖  ▸ 步骤 1                                                     ← 折叠
   ▸ 步骤 2
   ▸ 步骤 3
   ▸ 步骤 4
   ▸ 步骤 5
   ▸ 步骤 6
   ── 最终回复 ──
   完成. README ...

   ┌─ 展开 步骤 1 ────────────────────────────────────────────────┐
   │  💭 思考                                                      │
   │  用户要 3 件事: 1) 读 README 2) 写 hello.js 3) 跑 node        │
   │  🔧 read README.md → 100 行                                  │
   └────────────────────────────────────────────────────────────┘

   ┌─ 展开 步骤 2 ────────────────────────────────────────────────┐
   │  💭 思考                                                      │
   │  README 说 ...                                                │
   │  🔧 write hello.js → 4 行                                    │
   └────────────────────────────────────────────────────────────┘
   ... (其余 4 步)
```

**特点**:
- ✅ 保留"步骤 N"概览(用户能数 LLM 跑了几步)
- ✅ 每步默认折叠不占空间
- ✅ 跟当前 StepGroup 接近,改最少
- ❌ 比 A/B 多一层"步骤 N"虚构概念
- ❌ 当前就叫"步骤 N · 思考 X 次 · 调用 M 工具" — 这是 user 反馈不喜欢的

**改 StepGroup**: 🟢 小(改 ~30 行,StepGroup 改用 `<details>` 默认折叠)

## 对比总览

| 维度 | A 平铺流 | B Cursor 卡片 | C Claude Code web | D 混合 (details) |
|---|---|---|---|---|
| **Pi SDK 原生度** | 🟢 最高(就是平铺 event) | 🟡 中(自己组装) | 🔴 最低(藏 event) | 🟡 中(每 turn 一个 group) |
| **thinking 可见性** | ✅ 折叠可见 | ✅ 持续可见 | ❌ 完全藏 | ✅ 折叠可见 |
| **tool 视觉权重** | 🟡 中(跟 think 平级) | ✅ 高(独立卡片) | 🟡 中(nested) | 🟡 中(跟 think 平级) |
| **步骤概览** | ❌ 无 | ❌ 无 | ❌ 无 | ✅ 有(步骤 N) |
| **改 StepGroup 量** | 🟢 删 300 行 + 平铺 50 | 🟡 改 ~80 行 | 🟡 改 ChatMessage 主体 ~150 | 🟢 改 ~30 行 |
| **跟 user 反馈对齐** | ✅ "不要自己加工" | 🟡 部分对齐 | ❌ 反方向(更藏) | ❌ 保留 user 不喜欢的标题 |

---

## 我的推荐

**方案 A(平铺流)**,理由:
1. 最贴 Pi SDK event 流的本质(没有"步骤 N"这个虚构概念)
2. user 原话"参考 Pi 默认的形式来,不要用我自己加工的方式" — A 最 Pi 原生
3. 改动小(删 StepGroup 300 行,改 ChatMessage ~50 行平铺),风险低
4. 多次 think + tool 嵌套时**每块独立折叠**,视觉清爽
5. 跟 v0.5.0 + v0.5.0-PR3 沉淀的 minimalist / border-driven 风格一致

**你最想要哪种?或者**:
- 觉得 A 的"多次 think 折叠还是占空间"问题 → 看 B(全展开 thinking)
- 觉得 A 的"没有步骤概览"问题 → 看 D(每 step 折叠)
- 觉得 A 的"tool 视觉权重不够"问题 → 看 B(独立卡片)
- 想要 Claude Code web 那种干净 → 看 C(藏起来)
